# 座席決め：卓の向きと配置の自由度を上げる

作成日: 2026-07-29
対象: `日程調整アプリ/test/index.html`（座席決め）

## 背景

座席決めで実際の店のレイアウトを再現できない場面がある。ヒアリングの結果、詰まっているのは次の2点だった。

1. **長机が必ず横向き**。上段・下段が向かい合う形に固定されており、縦に並ぶ席を表現できない。
2. **卓の位置がマス目単位でしか決められず、間を空けられない**。

現状の実装上の制約は独立した2箇所にある。

- 列数は `Math.max(1, Math.min(parseInt(party.tableCols) || 1, 3, tables.length || 1))` で **最大3列かつ卓数以下**に制限されている（`renderSeatingBoard`）。卓が2つなら2列までしか作れない。
- `normalizeTableSlots` は「卓数が列数で割り切れるときは空きマスを作らず詰める」実装。**2卓×2列では隙間を保存できない**。

後者は過去に「卓が2つしかない際も空きスペースが表示される、奇数の場合のみにして」という指示を受けた結果であり、今回の要件と正面から衝突する。本設計はこの衝突を「配置を調整」モードで解消する。

## 要件

| # | 要件 |
|---|---|
| R1 | 長机を卓ごとに横向き／縦向きで選べる |
| R2 | 卓の配置を細かいマス目で決められ、卓と卓の間を空けられる |
| R3 | 配置の操作は現行の延長（卓をタップ → 空きマスの「ここへ移動」）。ドラッグ&ドロップは使わない |
| R4 | 通常表示の見た目は変えない。空きマスは「配置を調整」モード中だけ出す |
| R5 | 参加者側には調整用UIを一切出さない |

想定規模は**卓2〜4つ・20人前後**。拡大縮小や横スクロールの仕組みは不要。

### 非目標（YAGNI）

- L字・コの字・カウンター席などの新しい卓形状
- 自由座標での配置（ピクセル単位）
- 卓が複数マスを占有する仕組み
- 上座・下座の表示

## データモデル

追加するのは卓の1フィールドのみ。

```
卓:   { id, name, capacity, shape, split, slot,
        orient: 'h' | 'v' }     ← 追加。既定 'h'（横向き＝現状と同じ）
次会: { ..., tableCols,          ← 既存。上限3・卓数以下の制限を外す
        freeLayout: true }       ← 追加。ホストが配置を調整した印（既定は未設定＝false）
```

- `orient` は `shape === 'rect'`（長机）のときだけ意味を持つ。円卓は回転しても同一なので無視する。
- `orient` の無い既存データは `'h'` として扱う。**移行処理は不要**。
- 「配置を調整」モードは画面の一時状態であり保存しない（モジュール変数 `seatAdjustMode`）。

### 設計判断：縦向きは「見た目の90度回転」に留める

長机の席は「上段と下段が向かい合う」構造で、縦にしても「左列と右列が向かい合う」になるだけで**トポロジーは同一**である。したがって席の隣接関係は向きによらず変わらない。

この判断により、席替えの重複回避に使う `seatNeighborPairs(cap, shape, topCount)` と `arrangeTableSeats` は**変更不要**になる。縦向きを別の座席構造として扱った場合、既存の座席テスト29件が全て再検討対象になっていた。

## UI

### 卓の設定欄

現在「卓名 / 定員 / 長机・円卓 / 上下振り分け / ✕」が横一列に並ぶ。ここに向きのセレクタを足す。

```
[卓名] [定員] [長机▾] [横向き▾] [上4・下3▾] [✕]
                       ↑追加。長机のときだけ表示
```

長机で縦向きを選ぶと、振り分けの表記は「上4・下3」から**「左4・右3」**に変わる。中身は既存の `split` フィールドのままで、ラベルだけ向きに応じて出し分ける。

### 配置の調整

次会タブの下に「配置を調整」ボタンを置く（ホストのみ）。

| 状態 | 表示 |
|---|---|
| 通常 | 空けた隙間は**余白として残る**が、「空きスペース」の枠・ラベル・タップ判定は出ない |
| 調整モード中 | 隙間が「空きスペース」の枠として現れる。列数ボタンが 1〜6 に拡張。卓をタップ → 空きマスの「ここへ移動」で配置 |
| 調整を終える | ボタンを再度押すと通常表示へ戻る。**配置（`slot` と `tableCols`）は保存済みなので維持される** |

参加者側の表示は現状どおりで、調整用UIは出さない。

#### 隙間の扱い（重要）

「空きマスは調整モード中だけ出す」のは**枠とラベルの話**であり、隙間そのものは通常表示でも保たれる。隙間まで消すと、せっかく調整した配置が普段は見えず、機能の意味が無くなるため。

参加者向けには既に `<div class="seat-empty-slot ghost">`（枠なしの見えない占位）が存在するので、ホストの通常表示でもこれを使う。

過去の指示「卓が2つしかない際も空きスペースが表示される、奇数の場合のみにして」は、**自動採番で意図せず現れる空きマス**を消すためのものだった。ホストが明示的に空けた隙間はこれに当たらない。

両者は `slot` の値からは区別できない。卓を3つ作って1つ削除すると `slot=3` が残り、「ホストが意図的に空けた隙間」と見分けがつかないためである（これは元のバグそのもの）。したがって**意図を明示的に記録する**。

```
次会: { ..., freeLayout: true }   ← 追加。ホストが「配置を調整」で配置を決めた印
```

| `freeLayout` | `normalizeTableSlots` の挙動 |
|---|---|
| 未設定／false（既定） | **現状のまま**。卓数が列数で割り切れれば詰める |
| true | **詰めない**。`slot` の位置をそのまま使い、隙間を保持する |

`freeLayout` は調整モードで卓を移動したとき、または列数を変えたときに `true` になる。一度も調整していない次会は従来どおりの挙動なので、**既存テスト4件は変更せずに通る**。

卓を削除したときは `slot` を詰め直さない（`freeLayout` の次会ではホストの配置を崩さないため）。`freeLayout` でない次会は元々詰められるので、意図しない隙間は現れない。

## 描画

縦向きの長机は、既存の横向きマークアップを行と列で入れ替えた形で描く。

```
横向き（現状）              縦向き（追加）
┌─────────────┐          ┌───┬───────┬───┐
│ 席 席 席 席 │          │ 席│       │ 席│
├─────────────┤          │ 席│ TABLE │ 席│
│   TABLE     │          │ 席│       │ 席│
├─────────────┤          │ 席│       │   │
│ 席 席 席 席 │          └───┴───────┴───┘
└─────────────┘
```

- 座席チップの並び順（配列インデックス）は横向きと同一。`split` で決まる「多い側」が、横向きなら上段、縦向きなら左列になる。
- `TABLE` の文字は縦向きでは縦書き（`writing-mode: vertical-rl`）にし、卓の中心に置く。
- グリッドのマスは `align-items: start` とし、縦横の卓が混在しても各マスが上端で揃うようにする。

席替え・重複回避のロジックは変更しない。

## 変更する箇所

| 箇所 | 変更内容 |
|---|---|
| `renderSeatingTables` | 向きセレクタの追加。`split` のラベルを向きで出し分け |
| `renderSeatingBoard` | 縦向きの描画分岐。列数上限の緩和。調整モードの反映 |
| `renderSeatingPartyTabs` 付近 | 「配置を調整」ボタンの追加 |
| `normalizeTableSlots` | `freeLayout` 引数を追加。true なら詰めずに `slot` 位置を保つ |
| CSS | `.seat-longtable` の縦向き版、`TABLE` の縦書き、グリッドの `align-items` |

## テスト

| 対象 | 内容 |
|---|---|
| `tableRowCounts(t)`（新規・純粋関数） | 卓から「多い側／少ない側」の席数を返す。横縦・奇数偶数・円卓・`split` 未設定の組み合わせを固定する |
| `normalizeTableSlots` | 既存4件は**変更せず**通ること（`freeLayout` 未指定＝従来の挙動）。加えて `freeLayout=true` で「隙間が保持される」「末尾の隙間も残る」を追加 |
| 既存の座席テスト29件 | 変更なしで通ること（隣接関係を変えていない証明） |

### 実機検証（ヘッドレス）

1. 卓2つを作り、片方を縦向き・片方を横向きに設定する
2. 調整モードに入り、列数を広げて卓の間を空ける
3. 通常表示に戻し、空きマスが出ないこと・配置が保持されることを確認
4. 参加者画面で同じ配置が見え、調整用UIが出ないことを確認
5. 席替えを実行し、縦向きの卓でも隣接回避が働くことを確認

## リスク

| リスク | 対応 |
|---|---|
| 縦横の卓が混在するとマスの縦横比が揃わずラフに見える | `align-items: start` で上端を揃える。卓2〜4つの規模では許容範囲と判断 |
| 列数の上限を外すと、卓より多い列を指定して空きだらけになる | 調整モード中のみ 1〜6 に拡張し、通常時は現行の挙動を維持 |
| 詰め判定の変更で既存の詰め表示が壊れる | `freeLayout` を既定 false とし、既存テスト4件を変更せずに通ることを条件とする |
| 隙間を空けた後に卓を削除すると、`slot` に穴が残って余白だけが残る | `freeLayout` の次会でのみ起こる。ホストが意図して並べた配置を削除のたびに崩さないため `slot` は詰め直さず、不要な余白は調整モードで直す。`freeLayout` でない次会は従来どおり詰められるので影響しない |
