# メールアドレスでのアカウント登録

作成日: 2026-07-29
対象: `日程調整アプリ/test/index.html`、Firebase Auth の設定

## 背景

現在ログインできるのは Google のみで、ほかに匿名認証（ホスト専用URLの引き換え用）がある。
個人の Google アカウントを業務のツールに紐づけることへの抵抗が理由で、ログインをためらう利用者がいる。
Google を使わずにアカウントを作れる手段を用意する。

現状の把握:

- 有効なプロバイダは Google と匿名のみ。メール・電話は Firebase 側で未有効。
- ログインが必要な操作: イベント作成、マイイベント、振込先口座の保存、AI注文提案。
- 権限は `events.ownerUids` に **uid** を入れる方式で、プロバイダに依存しない。
- Firestore ルールと Cloud Functions は `sign_in_provider != 'anonymous'` という**否定形**で匿名だけを除外している。

## 要件

| # | 要件 |
|---|---|
| R1 | メールアドレスとパスワードで新規登録・ログインできる |
| R2 | 確認メールは送らない（登録した時点ですぐ使える） |
| R3 | Google アカウントとは別アカウントとして併存する（統合・紐付けはしない） |
| R4 | 未ログインの利用者が、ヘッダ・作成画面の注記・作成ボタン押下の3箇所からログインに進める |
| R5 | ログインの選択はモーダルで行い、作成途中の入力を失わせない |
| R6 | 追加費用を発生させない |

### 非目標（YAGNI）

- Google アカウントとメールアカウントの紐付け・統合
- 匿名アカウントからの引き継ぎ（昇格）
- 電話番号（SMS）認証 — 送信ごとに課金されるため R6 と衝突する
- 独自ドメインからのメール送信 — 外部サービスの契約が必要で R6 と衝突する
- 登録時の確認メール送信

## 方式

Firebase Auth のメール/パスワードプロバイダを有効化し、既存の Google と並列に置く。

```
Firebase Auth
├─ Google           （既存・変更なし）
├─ メール/パスワード  ← 追加
└─ 匿名             （既存・ホスト専用URL引き換え用）
```

| 操作 | API |
|---|---|
| 新規登録 | `createUserWithEmailAndPassword` |
| ログイン | `signInWithEmailAndPassword` |
| パスワード再設定 | `sendPasswordResetEmail`（「忘れた方」を押した時だけ） |
| 表示名の保存 | `updateProfile`（未入力ならメールの `@` より前を使う） |
| 確認メール | 送らない |

パスワードの保存・ハッシュ化・再設定トークンはすべて Firebase 側が持つ。アプリはパスワードを保持しない。

### 設計判断：パスワード再設定は残す

R2 で確認メールは送らないが、**再設定メールは残す**。これも無くすと、パスワードを忘れた時点でアカウントと作成済みイベントへ永久にアクセスできなくなる。
再設定は「忘れた時に本人が押す」導線なので、通常の利用では一通もメールが飛ばない。

### 匿名で開いている人が登録した場合

ホスト専用URLで匿名ホストになっている状態から新規登録すると、**匿名セッションは破棄され、新しいアカウントでログインし直した状態になる**。
匿名からの引き継ぎは非目標のため、その匿名アカウントが持っていたホスト権限は引き継がれない。
ホスト専用URLをもう一度開けば、新しいアカウントでホスト権限を取り直せる（`claimHostByCode` は uid を追加する方式のため）。
登録フォームにこの旨は書かない（該当する場面が限られ、文言が増えるほうが分かりにくくなるため）。ホスト専用URLを開き直せば復帰できることを検証項目に含める。

### 権限まわりは変更しない

`ownerUids` は uid で持っており、プロバイダに依存しない。
ルールと Functions の条件が「匿名を除外する」という否定形で書かれているため、メール認証（`sign_in_provider === 'password'`）は既存の条件をそのまま満たす。
**Firestore ルール・Cloud Functions・ホスト判定・マイイベント・精算の権限は一切変更しない。**

## UI

### 導線（3箇所すべてを同じモーダルに集約）

| # | 場所 | 変更後 |
|---|---|---|
| 1 | ヘッダ右上 | 「Googleでログイン」→「ログイン / 新規登録」。押すとモーダル。Google のロゴは方式を限定して見えるため外す |
| 2 | 各作成画面の注記（5箇所） | テキスト → 押せるボタン。「🔑 作成にはログインが必要です（ログイン / 新規登録）」 |
| 3 | 作成ボタン押下時 | 従来どおり保留 → モーダル表示 → ログイン後そのまま作成が続行 |
| 4 | AI注文提案の実行時（`invokeSuggestOrderPlan`） | 「Googleログインが必要です」→「ログインが必要です」に変え、モーダルを表示 |

④ は R4 に挙げた3箇所とは別に、コード上 `signIn()` を直接呼んでいる箇所。ここも同じモーダルに寄せる。

③ は既存の `resumePendingCreate`（作成内容を `sessionStorage` に退避してログイン後に自動実行する仕組み）をそのまま使う。
メール認証はページを離れないのでこの仕組みは本来不要だが、同じ経路を通すことで Google とメールで挙動が分岐しなくなる。

### モーダル

```
┌────────────────────────────┐
│  ログイン                ✕ │
│                            │
│  [ G  Googleでログイン    ] │
│  ──────── または ────────  │
│  メールアドレス [        ]  │
│  パスワード     [        ]  │
│  [       ログイン        ] │
│                            │
│  パスワードを忘れた方        │
│  アカウントをお持ちでない方は │
│  新規登録                   │
└────────────────────────────┘
```

「新規登録」でモーダル内が登録フォーム（表示名・メール・パスワード・パスワード確認）に切り替わる。画面遷移はしないので、作成途中の入力は保持される。

## 入力チェック

| 項目 | チェック |
|---|---|
| メール | 形式（`@` とドメイン）。空欄不可 |
| パスワード | **8文字以上**。登録時は確認用の再入力と一致すること |
| 表示名 | 任意。未入力ならメールの `@` より前 |

Firebase の既定は6文字以上だが、総当たり耐性が実用的に変わる下限として8文字を要求する。

## エラー表示

| コード | 表示 |
|---|---|
| `auth/email-already-in-use` | このメールアドレスは既に登録されています（Googleで登録済みの場合も含みます） |
| `auth/invalid-email` | メールアドレスの形式が正しくありません |
| `auth/weak-password` | パスワードは8文字以上にしてください |
| `auth/invalid-credential` / `auth/wrong-password` / `auth/user-not-found` | メールアドレスまたはパスワードが違います |
| `auth/too-many-requests` | 試行が多すぎます。しばらく待ってからお試しください |
| `auth/network-request-failed` | 通信に失敗しました。接続を確認してください |
| 上記以外 | ログインに失敗しました。しばらくしてからお試しください |

### 設計判断：ログイン失敗の理由を区別しない

`invalid-credential` / `wrong-password` / `user-not-found` を**同一の文言**にする。
分けて表示すると、総当たりで「どのメールアドレスが登録済みか」を調べられる（アカウント列挙）。

`email-already-in-use` は登録時にしか出ないため具体的に案内してよい。ただし **Google で同じメールを使っている場合もこのコードになる**ので、文言にその旨を含める。R3 のとおり紐付けはしないので、その場合は Google でログインしてもらう。

## 変更する箇所

| 箇所 | 変更内容 |
|---|---|
| `firebase-auth.js` の import | `createUserWithEmailAndPassword` / `signInWithEmailAndPassword` / `sendPasswordResetEmail` / `updateProfile` を追加 |
| ヘッダの `#signInBtn` | ラベル変更＋モーダルを開く |
| `.login-note`（5箇所） | 押せるボタンにする |
| `signIn()` | Google 専用のまま残し、モーダルから呼ぶ |
| 新規 `openAuthModal()` ほか | モーダルの開閉・ログイン/登録の切り替え・送信処理 |
| 新規 `validateAccountInput()` / `authErrorToJa()` | 純粋関数として切り出す |
| Firebase Auth 設定 | メール/パスワードプロバイダを有効化（Admin API から実施） |

Firestore ルール、Cloud Functions、`ownerUids` を使う既存処理は変更しない。

## テスト

| 対象 | 内容 |
|---|---|
| `validateAccountInput` | メール形式・パスワード8文字・再入力一致・表示名の既定値。境界と異常系 |
| `authErrorToJa` | 上表の対応付け。未知のコードで英語を露出させないこと。3つのコードが同一文言になること |

### 実機検証（ヘッドレス）

1. 未ログインで3箇所すべてからモーダルが開く
2. 新規登録 → その場でログイン状態になり、ヘッダに表示名が出る
3. ログアウトし、同じメール・パスワードで再ログインできる
4. 作成ボタン → モーダル → 登録 → そのままイベントが作成される
5. 作成したイベントの `ownerUids` に uid が入り、ホストとして編集できる
6. 誤ったパスワードで「メールアドレスまたはパスワードが違います」が出る
7. 既存メールでの登録が `email-already-in-use` の日本語で止まる
8. Google ログインが従来どおり動く（回帰確認）
9. パスワード再設定メールの送信が成功する（受信までは確認しない）
10. 匿名ホスト状態から登録すると新アカウントに切り替わり、ホスト専用URLを開き直せばホスト権限を取り直せる
11. コンソールエラー0件

検証用に作成したアカウントは、Admin API で削除して後片付けする。

## リスク

| リスク | 対応 |
|---|---|
| 確認メールを送らないため、他人のメールアドレスでも登録できる | 本アプリでメールアドレスはログインIDとしてのみ使い、本人確認の根拠にしない。権限は uid に紐づく |
| メールの打ち間違いに気づけず、再設定できなくなる | 登録フォームにその旨を明記する |
| Google と同じメールで登録できず戸惑う | `email-already-in-use` の文言に Google の可能性を含める |
| 総当たりでパスワードを試される | Firebase Auth 側の `too-many-requests` によるレート制限に委ねる |
| メール認証の有効化が他の認証経路に影響する | 権限条件が否定形（匿名を除外）のため既存条件は不変。検証項目8で Google の回帰を確認する |
